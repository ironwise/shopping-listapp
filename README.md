# 쇼핑 리스트

아이템 추가·삭제·체크가 되는 **단일 파일** 쇼핑 리스트 웹 앱. 목록은 Supabase(Postgres)에 저장된다.
`index.html` 하나에 마크업·스타일·로직이 모두 들어 있어, 파일을 더블클릭하면 그대로 열린다. 빌드 과정도 서버도 필요 없다.

## 기능

- 물건 추가 — 앞뒤·중간 공백은 하나로 정리하고, 최대 100자까지 받는다
- 완료 체크 — 글자 어디를 눌러도 체크된다 (작은 체크박스를 노릴 필요가 없다)
- 개별 삭제 / 완료 항목만 삭제 / 전체 삭제 (전체 삭제는 한 번 확인한다)
- 남은 개수와 전체 개수 표시
- **Supabase 저장** — 새로고침해도, 다른 기기에서 열어도 같은 목록이 보인다
- 라이트/다크 테마 자동 전환 (`prefers-color-scheme`)

### 중복 입력을 다루는 방식

같은 물건을 또 입력하는 건 보통 실수다. 그래서 항목을 하나 더 만들지 않고 기존 항목을 잠깐 강조해 알려준다. 단, **이미 체크해 둔 물건을 다시 입력하면 체크를 푼다** — "또 필요하다"는 뜻으로 본다. 공백과 대소문자 차이는 같은 물건으로 취급한다.

## 데이터베이스

Supabase 프로젝트 `shopping-list-app` (리전 `ap-northeast-2`) 의 `shopping_items` 테이블 하나를 쓴다.

| 열 | 타입 | 비고 |
|---|---|---|
| `id` | `uuid` | 기본키. 브라우저에서 만들어 보낸다 (서버 응답을 기다리지 않고 바로 그리려고) |
| `name` | `text` | 1–100자 (`check` 제약) |
| `done` | `boolean` | 기본값 `false` |
| `created_at` | `timestamptz` | 추가 순서. 브라우저가 직접 적는다 — 아래 설계 메모 참고 |

접근은 `index.html` 안의 URL 과 publishable 키로 한다. 둘 다 **공개되는 값**이고, 브라우저로 그대로 내려가는 걸 전제로 만들어진 키다. 실제 접근 제어는 테이블의 RLS 정책이 한다.

> ⚠️ **이 앱에는 로그인이 없다.** 그래서 RLS 를 `anon` 에게 읽기·쓰기 모두 열어 두었다 — 즉 **이 페이지를 여는 모든 사람이 목록 하나를 함께 쓴다.** 공개 데모라서 이렇게 두었다. 사용자별로 나누려면 Supabase Auth 를 붙이고 `user_id` 열을 추가해 정책을 `auth.uid()` 로 좁혀야 한다.

예전 버전은 `localStorage` 에 저장했다. 그 데이터가 남아 있으면 첫 로드에서 한 번 서버로 옮기고 키를 지운다 — 업데이트했다고 해서 적어 둔 목록이 사라지면 안 된다.

## 쓰는 법

바로 써 보기: **https://ironwise.github.io/shopping-listapp/**

내려받았다면 `index.html` 을 브라우저로 열면 끝이다. 단, 이제 목록을 불러오려면 네트워크가 필요하다.

개발·테스트용으로 http 로 띄우려면:

```bash
npm install
npm run serve      # http://127.0.0.1:4173
```

`file://` 로는 Playwright 와 Chrome 확장이 접근을 막기 때문에, 테스트할 때만 `serve.js` 로 같은 파일을 http 로 내보낸다.

## 테스트

Playwright 기반 E2E 테스트 25개. 빈 상태·추가·체크·삭제·중복·저장·접근성과 콘솔 오류, 그리고 서버가 실패할 때의 복구까지 덮는다.

```bash
npm test           # 헤드리스 실행
npm run test:headed
npm run test:ui
npm run report
```

테스트는 **실제 Supabase 프로젝트**를 쓴다. 네트워크가 없으면 전부 실패한다. 각 테스트가 시작할 때 `shopping_items` 테이블을 비우므로, 병렬로 돌리면 서로의 데이터를 지운다 — 그래서 `workers: 1` 로 순차 실행한다.

| 파일 | 역할 |

| `index.html` | 앱 전체 (마크업·스타일·로직) |

## 설계 메모

- **supabase-js 를 쓰지 않는다** — 빌드 없는 단일 파일을 유지하려고 PostgREST 를 `fetch` 로 바로 부른다. CDN 모듈 `import` 는 `file://` 로 열면 막혀서, 더블클릭으로 쓰는 경로가 깨진다.
- **화면을 먼저 바꾸고 서버에 반영한다** — 체크 한 번마다 왕복 지연이 그대로 보이면 쓰기 불편하다. 실패하면 바꾸기 전 상태로 되돌리고 알림 띠로 알린다.
- **`created_at` 을 브라우저가 적는다** — 서버 기본값 `now()` 에 맡기면 안 된다. 응답을 기다리지 않고 다음 입력을 받으니 여러 요청이 동시에 날아가고, 서버에 닿는 순서가 입력 순서와 달라진다. 그러면 새로고침했을 때 적어 둔 순서가 뒤바뀐다. 같은 밀리초에 두 개가 들어와도 섞이지 않게 1ms 씩 밀어 준다. 정렬에는 `id` 를 동점자로 함께 쓴다.
- **첫 로드가 끝날 때까지 입력을 잠근다** — 불러오기 전에 입력을 받으면 서버에 없는 항목이 화면에만 쌓인다. 불러오지 못했을 때는 오류와 "다시 시도" 버튼을 보여준다.
- **서버 응답도 외부 입력으로 본다** — 배열인지, 각 항목의 모양이 맞는지 검사하고 맞는 것만 살린다.
- **입력값은 `textContent` 로만 넣는다** — HTML 을 입력해도 태그로 해석되지 않는다.
- **접근성** — 체크박스와 삭제 버튼에 이름을 붙이고, 변경 사항을 `role="status"` 영역으로 안내한다. 키보드만으로 추가·체크가 된다.

## 요구 사항
