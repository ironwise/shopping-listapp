# 쇼핑 리스트

아이템 추가·삭제·체크가 되는 **단일 파일** 쇼핑 리스트 웹 앱.
`index.html` 하나에 마크업·스타일·로직이 모두 들어 있어, 파일을 더블클릭하면 그대로 열린다. 빌드 과정도 서버도 필요 없다.

## 기능

- 물건 추가 — 앞뒤·중간 공백은 하나로 정리하고, 최대 100자까지 받는다
- 완료 체크 — 글자 어디를 눌러도 체크된다 (작은 체크박스를 노릴 필요가 없다)
- 개별 삭제 / 완료 항목만 삭제 / 전체 삭제 (전체 삭제는 한 번 확인한다)
- 남은 개수와 전체 개수 표시
- `localStorage` 저장 — 새로고침해도 목록과 완료 상태가 유지된다
- 라이트/다크 테마 자동 전환 (`prefers-color-scheme`)

### 중복 입력을 다루는 방식

같은 물건을 또 입력하는 건 보통 실수다. 그래서 항목을 하나 더 만들지 않고 기존 항목을 잠깐 강조해 알려준다. 단, **이미 체크해 둔 물건을 다시 입력하면 체크를 푼다** — "또 필요하다"는 뜻으로 본다. 공백과 대소문자 차이는 같은 물건으로 취급한다.

## 쓰는 법

`index.html` 을 브라우저로 열면 끝이다.

개발·테스트용으로 http 로 띄우려면:

```bash
npm install
npm run serve      # http://127.0.0.1:4173
```

`file://` 로는 Playwright 와 Chrome 확장이 접근을 막기 때문에, 테스트할 때만 `serve.js` 로 같은 파일을 http 로 내보낸다.

## 테스트

Playwright 기반 E2E 테스트 22개. 빈 상태·추가·체크·삭제·중복·저장·접근성과 콘솔 오류까지 덮는다.

```bash
npm test           # 헤드리스 실행
npm run test:headed
npm run test:ui
npm run report
```

각 테스트가 시작할 때 `localStorage` 를 비우므로 같은 origin 을 공유한다. 병렬로 돌리면 서로의 데이터를 지우기 때문에 `workers: 1` 로 순차 실행한다.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 앱 전체 (마크업·스타일·로직) |
| `serve.js` | 테스트용 최소 정적 서버 |
| `playwright.config.js` | 테스트 설정 (포트 4173, 순차 실행) |
| `tests/shopping-list.spec.js` | E2E 테스트 |

## 설계 메모

- **저장 실패를 허용한다** — 사생활 보호 모드나 사이트 데이터 차단 설정에서는 `localStorage` 접근 자체가 예외를 던진다. 읽기·쓰기를 모두 감싸서, 저장이 안 되더라도 그 세션에서는 정상 동작한다.
- **저장된 값도 외부 입력으로 본다** — 불러올 때 배열인지, 각 항목의 모양이 맞는지 검사하고 맞는 것만 살린다. 저장소가 깨져 있어도 빈 목록으로 뜬다.
- **입력값은 `textContent` 로만 넣는다** — HTML 을 입력해도 태그로 해석되지 않는다.
- **접근성** — 체크박스와 삭제 버튼에 이름을 붙이고, 변경 사항을 `role="status"` 영역으로 안내한다. 키보드만으로 추가·체크가 된다.

## 요구 사항

Node.js 22 이상 (테스트 실행 시에만 필요하다)
